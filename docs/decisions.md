# Implementation decisions

- A2: Use one serialized, reconnecting ESL connection and never replay an interrupted command because repeating an originate can create a second billable channel. The protocol follows the [FreeSWITCH event socket reference](https://developer.signalwire.com/freeswitch/integration/event-socket/).
- A2: Reserve and store the provider UUID before origination, match events to that UUID, and tag every playback because provider events can precede command replies and duplicate playback notifications must not advance a later node.
- A2: Terminate the provider channel before releasing its logical slot; if hangup cannot be confirmed, retain the slot and expose the error so a reconnect or operator retry can reconcile it.
- Verification: Keep simulator processes and fake ESL/STT tests separate from operator trunk checks; Docker-dependent checks cannot run on this host until the operator installs Docker.
- A7: Use argon2id (64 MiB, three iterations, one lane) with environment-seeded email/password accounts because MKTR operates a single host and needs no external identity provider. Seeding never overwrites an existing account.
- A7: Store only SHA-256 hashes of random 256-bit session tokens, with an eight-hour expiry, rotation on sign-in and revocation on logout; this limits exposure if session rows are disclosed. Cookies always use `Secure`, `HttpOnly`, `SameSite=Strict` and the `__Host-` prefix.
- A7: Require authentication for every control-plane read and write, apart from health and separately bearer-authenticated media webhooks, because transcripts and operational state are also private. Use per-operator call limits and per-IP sign-in limits in this single-process deployment.
- A7: Keep telephony mode in the administrator's deployment environment and require a restart because switching adapters while calls are active can orphan channels. The authenticated admin endpoint reports this requirement and never enables live calls.
- A7: Use Caddy for automatic HTTPS and explicit immediate SSE flushing; a separate private proxy network allows Express to trust only Caddy's fixed address. See [Caddy reverse proxy documentation](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy) and [Express proxy trust guidance](https://expressjs.com/en/guide/behind-proxies/).
- A7: Use pino JSON logs with request IDs and secret-field redaction; return generic unexpected errors so operators can correlate failures without exposing internal messages to browsers.
