The renderer builds the destination expression directly from `CALLER_IDS` in `src/lib/domain.ts`. It accepts each approved full Singapore number with or without a leading plus. Every other destination is rejected. The TLS profile requires the `mktr-singtel-inbound` source ACL, defaults to the supplied account IP `52.77.0.62/32`, and rejects failed ACL checks without falling back to SIP digest authentication. That account IP is the initial configured source, **not confirmation of Singtel's actual inbound delivery IP**. Shawn must obtain the delivery source and DID format from Singtel and set `MKTR_SINGTEL_INBOUND_IP` accordingly; no broad CIDR or proxy-header trust is configured.

Shawn supplies these settings privately to both the API and gateway:

- `MKTR_INBOUND_CALLBACK_ENABLED`: defaults to false; enable only after routing, greeting and recording choices are reviewed.
- `MKTR_INBOUND_CLIP_FILE`: the UUID `.wav` leaf from an uploaded clip's `telephonyAssetUrl`, not its original MP3 preview. The API requires a ready clip and creates an immutable internal flow version that protects its bytes from deletion. Changing the greeting on a later startup creates a new version.
- `MKTR_INBOUND_RECORD_MESSAGE`: defaults to false. If enabled, the greeting must tell the caller that a message will be recorded and how MKTR uses it. Keep it disabled until the operator has reviewed that notice and the retention policy.
- `MKTR_INBOUND_MAX_MESSAGE_SECONDS`: defaults to 60, accepts 1–120. The message ends at this bound, after silence, on `#`, or when the caller hangs up. The whole channel still has the `MKTR_MAX_CALL_SECONDS` scheduled limit.
- `MKTR_RECORDING_RETENTION_DAYS`: defaults to 30, accepts 1–365. Recording files are UUID `.wav` leaves in the shared `recording-data` volume, mounted at `/app/storage/recordings` in the API and `/var/lib/freeswitch/recordings/sessions` in FreeSWITCH. The recording retention job and authenticated access use the C3 recording service.

The public dialplan marks the channel `mktr_direction=inbound_callback`, sets the approved destination, enforces SRTP, schedules its maximum duration, answers, plays the greeting, optionally records, and hangs up. `InboundCallbackTracker` consumes authenticated ESL events independently of the outbound orchestrator. It persists one `inbound_callback` call and immutable flow reference, counts the occupied slot, and finalizes on hangup. Duplicate events cannot create another call or outcome. It accepts recording metadata only for that channel's own UUID file and a positive recorded duration, including a final report arriving after an operator stop. Pino and aggregate outcome metrics update after persistence. The gateway's `max-sessions` follows the same configured 1–5 ceiling, including inbound legs.
